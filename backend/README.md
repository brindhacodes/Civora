# Civora Backend API

Express backend for Civora's citizen complaint workflow, backed exclusively by PostgreSQL 18.

## Setup

1. Install dependencies:

```bash
npm install
```

2. Configure `backend/.env`:

```dotenv
PORT=3000
DB_HOST=localhost
DB_PORT=5432
DB_NAME=civora
DB_USER=postgres
DB_PASSWORD=your_password
DB_POOL_MAX=10
DB_IDLE_TIMEOUT_MS=30000
DB_CONNECT_TIMEOUT_MS=5000
DB_SSL=false
```

3. Create the database and schema:

```bash
npm run init-db
```

`init-db` creates the `civora` database when it does not exist, then creates the users, complaints, comments, and complaint joins tables with constraints, foreign keys, and indexes.

4. Start and verify the API:

```bash
npm start
```

Open `http://localhost:3000/api/health` and `http://localhost:3000/api/complaints`.

## Database design

- `BIGINT GENERATED BY DEFAULT AS IDENTITY` primary keys
- timezone-aware `TIMESTAMPTZ` audit fields
- latitude, longitude, role, status, severity, and preference constraints
- foreign keys with deliberate delete behavior
- indexes for workflow filters, dates, locations, and every foreign-key column
- a bounded PostgreSQL connection pool configured through environment variables

## Main API routes

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/complaints` | Create and route a complaint |
| GET | `/api/complaints` | List/filter complaints |
| GET | `/api/complaints/:id` | Track one complaint |
| PUT | `/api/complaints/:id` | Update status, remarks, and proof |
| POST | `/api/complaints/:id/join` | Support an existing issue |
| POST | `/api/assign` | Assign an authority department |
| GET/POST | `/api/comments/:complaintId`, `/api/comments` | Complaint discussion |
| POST | `/api/auth/signup`, `/api/auth/login` | Citizen authentication |
| GET | `/api/health` | Service health |

## Database commands

```bash
npm run ensure-db       # create the configured database if missing
npm run init-db         # ensure database, schema, constraints, and indexes
```
